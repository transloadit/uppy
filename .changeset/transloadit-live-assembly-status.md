"@uppy/transloadit": minor

Keep `assemblyStatus` in plugin state accurate: advance `ok` to `ASSEMBLY_EXECUTING` when SSE reports that uploading finished, keep `progress_combined` across full status refetches while executing, expose the assembly error as `error` in plugin state (typed as `AssemblyStateError`; a network failure carries no API response fields), and close the assembly and clear its state as soon as `cancel-all` fires (even if the cancel request fails). `transloadit:assembly-cancel` is now actually emitted on cancel-all (it was declared but never fired), so `uppy.upload()` settles. `transloadit:assembly-cancelled` now fires after the assembly has been cleared, with the status as it was at the moment of cancelling. `transloadit:complete` is no longer emitted for an assembly that was cancelled or replaced while its final-status request was still in flight. If fetching the final status fails, the assembly now errors instead of leaving `uppy.upload()` pending. The assembly's `executing`, `metadata` and `finished` events now fire once per assembly, whether they come from SSE or polling, so `transloadit:complete` no longer fires twice with `waitForMetadata`, and a restored assembly re-derives them after a reload.
